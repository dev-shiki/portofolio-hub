Architecture Decision Records (ADRs)

Formal decision logs documenting context → decision → trade-offs → consequences. Demonstrating architectural maturity and system boundary governance.

ADR 0001 · Accepted

10-Domain Bounded Context Map

Context: Multi-product platform expansion risks super-app collapse.
Decision: Enforce 10 strict bounded contexts (Platform, Commerce, Operations, Finance, etc.).
Consequence: Zero cross-domain table sharing; all collaboration forced through APIs/events.

ADR 0006 · Accepted

Event Delivery: Transactional Outbox / Inbox

Context: Cross-domain events require reliable fan-out without losing messages on crashes.
Decision: Adopt SQL-based Outbox/Inbox pattern in the same DB transaction.
Consequence: Guaranteed at-least-once delivery and idempotent consumption without message broker overhead.

ADR 0007 · Accepted

Platform Owns Module Entitlements

Context: Duplicated feature-gating checks cause security drift across modules.
Decision: Centralize RBAC entitlement checks in Platform core service.
Consequence: Single audit point for billing/permission changes across all applications.

Universal Workflow Engine

AES-256-GCM + HMAC blind indexing + append-only audit log. Domain-agnostic — same engine handles procurement, HR, maintenance, capex.

// PII encrypted at application layer — plaintext never stored
model User {
  emailCiphertext  String  @map("email")            // 🔒 AES-256-GCM ciphertext
  emailBlindIndex  String  @unique @map("email_bidx")  // 🔎 HMAC-SHA256 for lookups
}

// BPE request — domain-agnostic state machine
model WorkflowRequest {
  domain        String          // "procurement" | "hr" | "maintenance"
  payload       Json            // typed domain-specific fields
  currentStatus WorkflowStatus  @default(draft)

  @@index([domain])
  @@index([currentStatus])
}

// Append-only step log — INSERT only, never UPDATE or DELETE

Immutable Ledger Trigger

PL/pgSQL trigger enforcing append-only semantics at PostgreSQL engine level. Cannot be bypassed by any application code, API key, or direct DB session.

PL/pgSQL (PostgreSQL) 
CREATE OR REPLACE FUNCTION enforce_ledger_immutability()
RETURNS TRIGGER AS $$
BEGIN
    IF TG_OP = 'UPDATE' THEN
        RAISE EXCEPTION
            'SECURITY VIOLATION: Ledger entry % cannot be modified. Session: "%".',
            OLD.id, session_user
            USING ERRCODE = 'restrict_violation';  -- SQLSTATE 23001
    ELSIF TG_OP = 'DELETE' THEN
        RAISE EXCEPTION
            'SECURITY VIOLATION: Ledger entry % cannot be deleted. Session: "%".',
            OLD.id, session_user
            USING ERRCODE = 'restrict_violation';
    END IF;
    RETURN NULL;
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;

CREATE TRIGGER trg_ledger_immutability
    BEFORE UPDATE OR DELETE ON event_wallet_ledger
    FOR EACH ROW EXECUTE FUNCTION enforce_ledger_immutability();

ADR 0001: 10-Domain Bounded Context Map

Status: Accepted · 2026-06-18

Context
The system spans multiple products. Without explicit boundaries, all of it collapses into one super-app or fragments into ad-hoc tables with no owner. Options: ~6 broad domains (too coarse), ~20 fine domains (too much overhead). 10 domains balances scale and legibility.

Decision
Adopt 10 domains: Platform · Commerce · Relationship · Operations · Content · Intelligence · Automation · Analytics · Finance · Integration. Each domain owns its model, data, rules, API, events, permissions, and lifecycle. The set is closed — a new ADR is required to add or remove.

Consequence
Every business record has a clear home. Cross-domain collaboration goes through events/APIs, never through shared tables. Platform remains a trust layer, not a super-monolith.

ADR 0006: Transactional Outbox / Inbox

Status: Accepted · 2026-06-18

Context
Domains must collaborate through events, never shared tables. A single paid-order event fans out to seven domains. In-process emit loses events on crash. A broker is premature overhead.

Decision
Each emitting domain owns {domain}_outbox, written in the same DB transaction as the state change. Each consuming domain owns {domain}_inbox, keyed by event ID — making consumption idempotent. A real broker can be added later without rewriting either table.

Consequence
No event is lost on crash. No event is processed twice. No new infrastructure at current scale.

ADR 0007: Platform Owns Module Entitlements

Status: Accepted · 2026-06-18

Context
If each module implements its own entitlement check, the logic diverges over time, edge cases are handled inconsistently, and a billing change requires updates across all modules.

Decision
Platform is the single source of truth for module entitlements. Any module calls the Platform entitlement service or reads its cache — never maintains its own entitlement state.

Consequence
Billing changes propagate automatically. Entitlement logic is tested once, in one place. Modules become simpler — they make a query, not a policy decision.

AI Test Generation & Specification Bias

Undergraduate Thesis · Empirical Study

Research Question
Do LLM-generated test suites systematically overfit to the happy path described in a specification, while consistently failing to cover edge cases and negative test paths?

Methodology
LLM prompting with varied temperature and prompt structures → coverage analysis against human-authored test suites → reproducibility testing across multiple sessions.

Key Findings
Happy-path bias is consistent and measurable. Deterministic sampling (temperature=0) produces reproducible bias — not unbiased output. Specification quality is the dominant variable: ambiguous specs produce the worst AI coverage regardless of model.
