Universal Workflow Engine

AES-256-GCM + HMAC blind indexing + append-only audit log. Domain-agnostic — same engine handles procurement, HR, maintenance, capex.

Prisma (PostgreSQL) 
// PII encrypted at application layer — plaintext never stored
model User {
  emailCiphertext  String  @map("email")            // 🔒 AES-256-GCM ciphertext
  emailBlindIndex  String  @unique @map("email_bidx")  // 🔎 HMAC-SHA256 for lookups
}

// BPE request — domain-agnostic state machine
model WorkflowRequest {
  domain        String          // "procurement" | "hr" | "maintenance"
  payload       Json            // typed domain-specific fields
  currentStatus WorkflowStatus  @default(draft)

  @@index([domain])
  @@index([currentStatus])
}

// Append-only step log — INSERT only, never UPDATE or DELETE
model ApprovalHistory {
  previousStatus WorkflowStatus
  newStatus      WorkflowStatus
  executedAt     DateTime  @default(now())

  @@index([requestId])
}

Immutable Ledger Trigger

PL/pgSQL trigger enforcing append-only semantics at PostgreSQL engine level. Cannot be bypassed by any application code, API key, or direct DB session.

PL/pgSQL (PostgreSQL) 
CREATE OR REPLACE FUNCTION enforce_ledger_immutability()
RETURNS TRIGGER AS $$
BEGIN
    IF TG_OP = 'UPDATE' THEN
        RAISE EXCEPTION
            'SECURITY VIOLATION: Ledger entry % cannot be modified. Session: "%".',
            OLD.id, session_user
            USING ERRCODE = 'restrict_violation';  -- SQLSTATE 23001
    ELSIF TG_OP = 'DELETE' THEN
        RAISE EXCEPTION
            'SECURITY VIOLATION: Ledger entry % cannot be deleted. Session: "%".',
            OLD.id, session_user
            USING ERRCODE = 'restrict_violation';
    END IF;
    RETURN NULL;
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;

CREATE TRIGGER trg_ledger_immutability
    BEFORE UPDATE OR DELETE ON event_wallet_ledger
    FOR EACH ROW EXECUTE FUNCTION enforce_ledger_immutability();

ADR 0001: 10-Domain Bounded Context Map

Status: Accepted · 2026-06-18

Context
The system spans multiple products. Without explicit boundaries, all of it collapses into one super-app or fragments into ad-hoc tables with no owner.

Decision
Adopt 10 domains: Platform · Commerce · Relationship · Operations · Content · Intelligence · Automation · Analytics · Finance · Integration. Each domain owns its model, data, rules, API, events, permissions, and lifecycle.

Consequence
Every business record has a clear home. Cross-domain collaboration goes through events/APIs, never through shared tables.

ADR 0006: Transactional Outbox / Inbox

Status: Accepted · 2026-06-18

Context
Domains must collaborate through events, never shared tables. Outbox/Inbox guarantees durable event delivery without a heavy message broker at current scale.
